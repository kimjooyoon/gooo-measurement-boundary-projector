# Release evidence contract

The release is PR-first. A work branch opens a pull request, the pull-request workflow must pass, and the merged `main` workflow must pass before an annotated release tag is pushed. The tag workflow checks out the tag, verifies that it is an annotated tag, builds a source archive and manifest, creates the GitHub release as a draft, audits asset digests, publishes it, and verifies `draft=false`, `prerelease=false`, and `immutable=true`.

The workflow preserves failed runs, tags, and draft releases. It never deletes a failed release or rewrites an existing release's assets. All GitHub API writes use `github.token`; no cross-project required gate is used.

The additive v0.2.0 release is bound to the v2 contract and its exact `12`-case denominator (`4 CLOSED`, `4 UNKNOWN`, `4 REFUTED`). Its manifest preserves the v1 ten-case history, the prior mutable/immutable release snapshots, and the one historical `OPERATIONAL_REFUTED` record. The optional v0.49 input is recorded as `168000ms` actual main-lock versus `0ms/0ms` product receipt conflict with `UNKNOWN/MEASUREMENT_SCOPE_MISMATCH`; it is not a required gate.

The release evidence artifact includes the tag object SHA, commit SHA, run ID, job names, artifact names and digests, release ID, asset IDs, immutable flag, semantic IR digest, conformance distribution, v0.48 conflict result, generated single-authority receipt digest, and the complete zero-authority vector. It also preserves the operational refutation that the initial implementation push preceded its PR: `pr_first_conformance=REFUTED`, `OPERATIONAL_REFUTED exact_count=1`, stage `AUTHORING`, step `OPEN_IMPLEMENTATION_PR_BEFORE_MAIN_INTEGRATION`, reason `INITIAL_IMPLEMENTATION_PUSH_PRECEDED_PR`, initial main SHA `8c63fb3abb6f6026bbf274bc6b938c54b4fca3de`, and run `33540259958`.
